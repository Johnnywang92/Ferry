## 2. 无开发者账号的连带后果(需要你知情)

`v2.3` 里有两处出口标准现在无法成立,已按实际情况改写:

- **M0b 出口标准**原为"逐个签名 + Hardened Runtime + 公证跑通" → 改为"**逐层 ad-hoc 签名 + Hardened Runtime 下本地产物可启动**"。公证(Notarization)移出本期范围。
- **M6 交付**原含"公证打包 + Sparkle 自动更新" → Sparkle 仍可用(它依赖 Sparkle 自己的 EdDSA 签名密钥,不依赖 Apple 账号),但**更新包同样未经公证**。
- **实际分发限制**:未公证的 app 在别人的 Mac 上会被 Gatekeeper 拦截,用户需手动放行(右键打开,或 `xattr -d com.apple.quarantine`)。这与 D2=B"通用客户端发布"存在张力——面向陌生用户的发布体验会受损,而 Mac App Store 上架(D2=C)本期完全不可行。
- **测试环境风险**:M1' 要测 Keychain 与 `ssh-agent`,ad-hoc 签名与正式 Developer ID 产物在 Keychain 访问组、code requirement 稳定性上行为不同。**决定**:M1' 起在本地用固定自签证书(非 ad-hoc)做 Keychain 相关测试,避免每次重建后 Keychain 条目失效;若后续购买账号,需在 M6 前追加一轮"真实签名环境复测"。
